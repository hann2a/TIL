# TIL: WSL(Windows Subsystem for Linux) 첫 정리 — 장단점과 활용 방향

## 한 줄 요약
WSL은 Windows 위에서 Linux 개발 환경을 거의 그대로 제공하는 기능이며, 문서/툴체인이 Linux 기준인 작업을 환경 꼬임 없이 수행하기 좋다.

---

## WSL을 쓰는 이유(장점)

### 1) Linux 기준 개발 가이드가 그대로 동작
대부분의 개발/서버/ML 문서가 Linux 기준이기 때문에, WSL에서는 설치/실행 방법을 그대로 따라가기 쉽다.

### 2) Python/CLI 설치가 예측 가능해짐
Windows에서는 PATH, pip.exe 위치, 여러 Python 설치(공식/Store/conda), Git Bash 환경 등으로 CLI가 자주 꼬인다.  
WSL에서는 python3 -m venv, pip install 등 표준 패턴이 안정적으로 동작한다.

### 3) 배포 환경과 유사(리눅스 서버/Docker)
실제 배포가 Linux 서버/Docker 위에서 이뤄지는 경우가 많아, 로컬 개발 환경과 배포 환경 차이를 줄일 수 있다.

### 4) GPU 있는 경우 WSL2에서 CUDA 사용 가능
NVIDIA GPU(예: RTX 4050 Laptop GPU)가 있으면 WSL2에서도 nvidia-smi로 GPU를 인식하고, PyTorch/Transformers를 GPU로 돌리는 구성까지 가능하다(드라이버/설정 필요).

## 주의할 점(단점/함정)

### 1) 파일 위치 원칙이 중요
WSL에서 성능/호환성 관점으로는 프로젝트를 WSL 파일시스템(홈 디렉터리)에 두는 것이 유리하다.

- 권장: ~/projects/<repo> (WSL 내부)
- 지양: /mnt/c/... 아래에서 직접 개발(빌드 산출물 많을수록 느리거나 권한/감시 이슈 가능)

### 2) Windows/WSL 혼용이 꼬임의 원인
같은 프로젝트를 두고 Windows에서 패키지 설치/실행하고, WSL에서 또 설치/실행하면 충돌 가능성이 높다.  
한 프로젝트는 WSL에서 설치/실행으로 통일하는 편이 안정적이다.

### 3) 네트워크/DNS 이슈가 가끔 발생
WSL에서 GitHub/PyPI 접속이 Network is unreachable 또는 443 연결 실패로 막히는 경우가 있다.  
이때는 wsl --shutdown, 재부팅, DNS 설정 조정 등이 필요할 수 있다.

## 내가 정한 운영 규칙(오늘 기준)

### 1) 작업 루트는 ~/projects
- ~/projects 아래에 repo를 일괄 관리
- 예: ~/projects/kaggle, ~/projects/planting-grass.github.io

### 2) 가상환경은 프로젝트별로 만든다
루트에 공용 .venv를 두지 않고, 각 repo 폴더 안에 .venv를 만든다.

```bash
cd ~/projects/<repo>
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
```

### 3) VS Code는 WSL 연동으로 연다
WSL 터미널에서:

```bash
code .
```

code가 없으면 Windows VS Code에 Remote WSL 확장(WSL) 설치 후, code 커맨드를 PATH에 설치한다.  
대안으로 Windows 탐색기 열기:

```bash
explorer.exe .
```

## 기본 사용 흐름(자주 쓰는 커맨드)

### git clone → venv 생성 → pip 업데이트
```bash
cd ~/projects
git clone <repo_url>
cd <repo>
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
```

### WSL 상태/배포판 확인(Windows PowerShell)
```powershell
wsl -l -v
wsl --shutdown
```

### GPU 인식 확인(WSL Ubuntu)
```bash
nvidia-smi
```

## 오늘 겪은 문제 & 교훈

### 1) Windows에서 CLI가 설치돼 있는데 실행이 안 됨 (PATH 문제)
py -m pip는 되는데 pip 자체가 안 잡히는 현상은 PATH에 ...Python311\Scripts가 없어서 생길 수 있다.  
WSL로 넘어오면 이런 종류의 PATH 꼬임이 줄어든다(단, WSL 내에서도 code 같은 커맨드는 별도 설정이 필요할 수 있음).

### 2) WSL에서 GitHub/PyPI 접속 불가
git clone에서 443 연결 실패, pip에서 Network is unreachable가 발생할 수 있다.  
우선순위 조치:
- Windows PowerShell에서 wsl --shutdown
- 재부팅 후 재시도
- DNS 문제면 /etc/resolv.conf 설정 조정 검토
