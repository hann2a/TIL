## 바이브 코딩으로 빌드 
바이브 코딩으로 해당 사이트를 배포 성공하였다 

https://hann2a.github.io/algorithm-tracker/

### 사이트를 만든 이유
- ai가 발전한 만큼 디자인을 떠올렸을 때 바로 빌드할 수 있을 것 같은데 계속 막히는 부분이 있고, gpt로 부족하다는 생각이 들었다. 그래서 antigravity를 사용하여 디버깅을 해보기로 했다. 

### 초기 실패 
- 처음에 한 생각은 figma make로 코드를 만들고 그걸 살려서 페이지를 배포할 수 있을 것 같았다. 그래서 처음에는 zip으로 만들어서 gpt에 제공해서 지킬 기반으로 고쳐달라고 했다. 여기서 가장 시간이 많이 걸렸는데, 빌드에 필요한 요소를 수정 사항을 반영하면서 계속 빠뜨려서 깃헙 설정, css, 기타 토큰 설정이 마구 꼬이면서 디버깅 지옥이 시작되었다. 그래서 기본 설정 고치기부터 antigravity를 쓰기 시작해서 진행이 되었다. 
- antigravity로 디버깅하면서 피그마 메이크로 만든 걸 사이트로 배포해서 참조하라고 하자 훨씬 효율적이게 되었다. antigravity는 직접 브라우저에 접속해서 js 코드나 반환되는 정보를 확인할 수 있기 때문에 시간이 걸리더라도 훨씬 정확한 디버깅을 했다. 커밋과 푸쉬는 직접했는데 어쨌든 지금 어느 걸 하는지 확인하면서 할 수 있으므로 여기까지의 자동화는 아직 불필요하다는 생각이 들었다. 

### 이 프로젝트 하면서 ai 프롬프팅의 결론 
- 잘 모르겠지만 초기 설계부터 antigravity로 하고 의문이 드는 부분을 확인하고 미리 고친 다음에 시작하는 게 디버깅 시간을 줄이는데 도움이 될 것 같다. 
- 또한 기존의 레거시 프로젝트나 ai 프로젝트 폴더에서 antigravity에게 가이드나 공부 문서를 만들어달라고하면 굉장히 정확하게 만들어준다. 리드미 뿐 아니라 어느 정도 바이브 코딩으로 사이트를 구현하고, 반대로 처음부터 만들어보는 방식이 공부하는 데 큰 도움이 되지 않을까 싶다. 물론 실존하는 사이트를 클론 코딩하는데도 큰 도움이 될 것 같다. 다만, 오늘 구현한 건 프론트 쪽이므로 백엔드 쪽은 디버깅을 어떻게 할지 모르겠다. 

## 해당 프로젝트를 하면서 새롭게 공부한 정보 

### 지킬 
- github의 창업자 중 한 명이 블로그 하나 쓰는데 DB까지 필요한가?라는 의문을 갖고 jekyll을 만들었다고 한다. 

### Tailwind
- 이름 짓기를 포기하자는 아이디어에서 시작되었고, 아주 작은 단위를 레고처럼 조립한다. 

### SSR
- 우리 프로젝트의 경우 `jekyll build` 명령이 실행될 때 Ruby가 마크다운 파일을 읽어서 `index.html`이라는 완성된 문서를 만들어낸다. 
- 사용자가 사이트에 들어오자마자 내용이 뜨고, 검색 엔진이 내용을 아주 잘 읽는다. 
- 우리 프로젝트는 배포할 때 한 번만 그리는 SSG, Static Site Generation 방식을 쓴다. 

### CSR
- 브라우저가 자바스크립트를 다운 받아서 스스로 화면을 그리는 것을 의미한다. 
- 우리 프로젝트에서는 연속 문제 풀이 기능이 여기에 해당한다. HTML에는 숫자가 비어있지만 사용자가 접속하면 자바스크립트가 `postDates` 배열을 분석해서 글자를 화면에 채워넣는다. 
- 장점은 페이지를 새로고침 안해도 내용이 바뀌고 단점은 자바스크립트가 실행되기 전까지 내용이 안 보일 수 있다. 

### jekyll의 collections
- `_posts` 외에도 `collections/projects`를 쓰면 날짜별로 정렬되지 않는 나만의 데이터 베이스를 만들 수 있다. 
- 대부분의 지킬 테마에 안 들어가 있어서 확인해야되고 `_config.yml`파일에 추가하면 된다. 
```yml
collections:
  projects:
    output: true
```

### custom plugins
- `_plugins` 폴더에 `.rb` 파일을 넣으면 기능을 확장할 수 있다. 아래와 같은 코드를 쓰면 유튜브 영상이 뜨게 할 수 있다. 
```ruby
class YouTube < Liquid::Tag
  def render(context)
    "<iframe src='...'></iframe>"
  end
end
```

## 프로젝트 파일 설명 
### Gemfile
- 이 사이트를 빌드하려면 지킬 엔진이 필요하다고 기록한 영수증
- bundle install을 하면 이 내역대로 도구 설치함 

### package.json 
- Tailwind CSS 번들러를 돌리기 위한 설정 
- npm run build 

### _config.yml 
- `baseurl` 설정이 틀리면 스타일, 이미지, 링크가 전부 꺠진다. 

### _layouts/default.html 
- 모든 페이지의 공통 껍데기. 여기에 `<script>` 태그 넣으면 사이트 전체에 적용됨

### `assets/css/index.css`
- 빌드 과정을 거쳐야 진짜 CSS가 된다. 이거 원본 파일 

### 빌드 과정 시뮬레이션 
- RUNNER 시작: 깃허브가 리눅스 컴퓨터 켬 
- 재료 준비: Ruby(Jekyll), Node(Tailewind)를 설치 
- `npm run build`를 먼저 실행 HTML 파일을 보고 사용된 클래스만 뽑아서 `output.css` 만듦 
- `jekyll build`가 실행됨. Liquid 변수를 실제 값으로 바꾸고, 레이아웃에 끼워넣어 최종 HTML 만듦 
- 완성된 _site 폴더를 Github Pages 서버로 전송 

### Liquid
- Shopify가 만든 템플릿 엔진이고 Jekyll이 이를 채택함
