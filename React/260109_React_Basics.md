## 💡 오답 노트 및 성찰

오늘 진행한 React 기초 퀴즈에서 13문제 중 5문제를 맞췄습니다. HTML과 유사하다는 생각에 가볍게 접근했다가, 개념적인 부분에서 많은 오답이 있었습니다. 헷갈렸던 부분과 잘못 이해하고 있었던 점들을 차분히 정리해 봅니다.

### 1. React의 정의
단순히 프레임워크라고 생각했으나, 정확한 정의는 **"UI(화면)을 만드는 JavaScript 라이브러리"**였습니다. 
핵심은 **'컴포넌트'**라는 단위로 화면을 조각내어 조립한다는 점입니다.

### 2. JSX 내부의 JavaScript
변수를 사용할 때 중괄호 `{ }`가 필수라는 점을 간과했습니다. 이를 생략하면 단순 텍스트로 렌더링된다는 것을 확인했습니다.
- `<h1>Hello, {name}</h1>` (올바른 예)

### 3. State(상태)의 본질
State를 '변경 불가능한 데이터'로 오해하고 있었습니다. 
정확히는 컴포넌트가 **기억**하고 있으며, 상황에 따라 **변경 가능**한 데이터입니다.
비유하자면 '통장'과 같아서, 내가 직접 관리하고 잔액 변동이 가능한 데이터라고 이해했습니다.

### 4. HTML과 JSX의 차이점
문법이 유사해 보여 혼동하기 쉬우나, JavaScript 환경에서 동작하므로 엄격한 규칙이 존재합니다.

| HTML | JSX | 이유 |
|------|-----|------|
| `class="box"` | **`className="box"`** | `class`가 JavaScript 예약어이기 때문 |
| `for="input"` | **`htmlFor="input"`** | `for` 반복문 키워드와 겹치기 때문 |
| `onclick="fn()"` | **`onClick={fn}`** | camelCase 표기법 및 함수 자체 전달 필요 |
| `<img src="...">` | **`<img src="..." />`** | 태그를 닫지 않으면 에러 발생 |

### 5. Props와 State의 구분
두 개념의 특징을 정확히 반대로 알고 있었습니다. 다시 정리합니다.

- **Props**: 부모 컴포넌트로부터 전달받는 데이터. 읽기 전용이며 자식 컴포넌트에서 수정할 수 없습니다. (마치 받은 택배처럼 내용물을 바꿀 수 없음)
- **State**: 컴포넌트 내부에서 생성하고 관리하는 데이터. 내가 직접 수정하고 관리할 수 있습니다. (내 지갑처럼 관리 가능)

## 🔑 주요 학습 내용 (Key Concepts)

교재(`teach.md`)를 읽으며 새롭게 정리한 핵심 개념들입니다.

### 1. React 사용 이유
- **선언적(Declarative)**: 구체적인 과정보다 '무엇을 보여줄지'에 집중할 수 있습니다.
- **자동 업데이트**: 데이터가 변경되면 화면이 자동으로 갱신됩니다. DOM을 직접 조작하는 번거로움이 없습니다.
- **Virtual DOM**: 가상 DOM을 통해 변경된 부분만 효율적으로 실제 화면에 반영합니다.

### 2. 컴포넌트 규칙
1. **함수명은 대문자로 시작**: 소문자로 시작하면 일반 HTML 태그로 오인될 수 있습니다.
2. **JSX 반환 필수**: 화면에 렌더링될 내용을 반드시 반환해야 합니다.

### 3. 리스트 렌더링 시 주의점
- `map()` 함수 사용 시 각 항목에 고유한 **`key`** 값을 부여해야 합니다. 
- 이는 React가 각 항목을 식별하여 효율적으로 업데이트하기 위함입니다.

### 4. useEffect 활용
- 화면에 나타나거나 사라질 때, 혹은 특정 값이 변할 때 실행되는 코드입니다.
- **의존성 배열(`[]`)**에 따라 실행 시점이 달라집니다.
  - `[]`: 마운트 시 1회 실행
  - `[value]`: 해당 값이 변경될 때마다 실행
